# 运行部署说明

## 一 环境准备

Windows 需要 JDK 17、Maven 3.9、Node.js 18或以上、MySQL Server 8.0或以上，以及 MySQL 客户端。MySQL服务需要先启动。Maven和Java加入PATH，设置JAVA_HOME指向JDK 17。

在命令提示符检查：

```bat
java -version
mvn -version
node -v
mysql --version
```

后端默认8091，测试页面默认5179。测试前端仅使用Node内置模块，无需安装npm依赖。本项目无需8080业务服务或MinIO。

## 二 一键导入数据库

双击 `database/import-database.bat`。输入数据库地址、数据库名、用户名和密码；默认地址127.0.0.1、数据库burn_treatment、用户root。端口默认3306。密码输入不会显示，也不写进命令行历史。

若MySQL客户端不在PATH，脚本先检查默认安装目录，再要求输入mysql.exe完整路径。账号需要CREATE DATABASE、CREATE TABLE及配置数据导入权限。

脚本创建数据库和以下11张表，并导入当前配置数据：

| 表名 | 用途 |
|---|---|
| llm_disease | 烧伤和瘢痕病种配置 |
| llm_indicator | 指标名称、编码、来源、值域、必填标记等 |
| llm_indicator_value_option | 指标取值及对应提取依据 |
| llm_indicator_group | 指标组 |
| llm_indicator_group_item | 指标组成员及条件 |
| llm_decision_tree | 决策树定义 |
| llm_decision_node | 节点及执行规则 |
| llm_decision_node_edge | 节点连线与条件 |
| llm_decision_tree_dependency | 跨树依赖 |
| llm_decision_tree_dependency_condition | 跨树依赖条件 |
| llm_decision_tree_indicator | 树与指标的关联 |

SQL只包含这11张表，不包含患者、病例、图片、运行记录或旧报告模板库。所有当前配置字段和指标取值依据保持原样。

**已有库保护：**只要目标库包含上述任意表，脚本就停止，不删除、不覆盖。已有库可以选择新的数据库名；不要为了导入直接删除同门已有表。导入到新库后，要把Java数据库连接改成这个库。SQL不包含DROP TABLE或DROP DATABASE；如果导入中途失败，已创建的部分表不会自动回滚，修复问题后用新数据库重试。

**端口不是3306：**在命令提示符运行：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File database\import-database.ps1 -DbPort 3307
```

导入成功会显示病种、指标和树的数量。当前配置包含烧伤74个指标、瘢痕78个指标；指标ID与原库保持一致。

## 三 配置数据库和千问

复制 `burn-ai-service/config-example.bat` 为同目录的 `config-local.bat`，用记事本编辑。启动BAT会自动读取这个本地文件。文件被Git忽略，请勿将真实密码或key提交到仓库。

千问示例：

```bat
@echo off
set "BURN_AI_DB_USERNAME=root"
set "BURN_AI_DB_PASSWORD=自己的MySQL密码"
set "BURN_AI_PROVIDER=qwen"
set "BURN_AI_QWEN_ENABLED=true"
set "BURN_AI_QWEN_API_KEY=自己的千问API_KEY"
set "BURN_AI_QWEN_MODEL=qwen-plus"
set "BURN_AI_VLLM_ENABLED=false"
```

千问使用DashScope兼容接口，默认地址为 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`。若账号使用其他地域或兼容端点，设置 `BURN_AI_QWEN_ENDPOINT` 为账号对应的完整Chat Completions地址。模型名由 `BURN_AI_QWEN_MODEL` 指定，必须是当前账号可调用的模型。已有千问和vLLM客户端均支持流式调用。

使用其他数据库地址、端口或库名时，增加：

```bat
set "BURN_AI_DB_URL=jdbc:mysql://127.0.0.1:3306/burn_treatment?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true"
```

按实际情况修改127.0.0.1、3306和burn_treatment。`set "名称=值"` 的引号需要保留，使URL中的&按普通字符处理。密码含 `%` 时在BAT文件中写作 `%%`；更复杂的凭据可通过IDE环境变量填写。

## 四 使用 vLLM

在同一个 `config-local.bat` 中将模型配置改为：

```bat
set "BURN_AI_PROVIDER=vllm"
set "BURN_AI_QWEN_ENABLED=false"
set "BURN_AI_VLLM_ENABLED=true"
set "BURN_AI_VLLM_ENDPOINT=http://127.0.0.1:8000/v1/chat/completions"
set "BURN_AI_VLLM_MODEL=Qwen3.5-9B"
set "BURN_AI_VLLM_API_KEY=EMPTY"
```

模型在另一台机器时，把127.0.0.1改成能访问的模型服务器IP，例如 `192.168.8.211`。模型名大小写必须与vLLM的served-model-name一致。使用前先启动模型服务；Java启动成功不表示模型已启动。vLLM设置鉴权时把EMPTY换成实际key。

所有配置同时可通过 `burn-ai-service/src/main/resources/application.yml` 调整，但建议使用本地配置文件。改变配置后先关闭再重启Java。

## 五 Windows 启动与关闭

双击 `burn-ai-service/start-backend.bat`。脚本先用Maven编译，然后后台启动Java，并等待8091监听。首次编译需要联网下载依赖。显示 `[OK] Started` 后可使用接口；数据库和模型仍需通过实际请求验证。

双击 `burn-ai-service-test-ui/start-test-ui.bat`，然后浏览器打开 http://127.0.0.1:5179 。选择烧伤或瘢痕，输入护士文本和Python图片检测JSON，点击指标提取，再编辑指标并生成报告。页面展示耗时、日志和八段报告。

| 操作 | 后端 | 测试前端 |
|---|---|---|
| 启动 | start-backend.bat | start-test-ui.bat |
| 状态 | status-backend.bat | status-test-ui.bat |
| 关闭 | stop-backend.bat | stop-test-ui.bat |

BAT内部调用PowerShell辅助程序，日常只需双击BAT。窗口保留启动结果，避免闪退。日志和PID在对应项目 `.runtime` 目录；停止脚本只关闭自己记录且核对过路径的进程。

工具未加入PATH时，在本地配置文件指定：

```bat
set "JAVA_CMD=C:\自己的JDK目录\bin\java.exe"
set "MAVEN_CMD=C:\自己的Maven目录\bin\mvn.cmd"
```

前端工具或后端地址需调整时，复制前端 `config-example.bat` 为 `config-local.bat`：

```bat
set "NODE_CMD=C:\自己的Node目录\node.exe"
set "BURN_AI_BACKEND=http://127.0.0.1:8091"
set "TEST_UI_PORT=5179"
```

直接连接5090已开放的服务可将BURN_AI_BACKEND设为 `http://192.168.8.211:8091`。本地运行默认无需EasyTier。更改Java端口设置BURN_AI_PORT，并相应更改前端代理地址。

## 六 接口验证

Windows命令提示符验证配置库查询：

```bat
curl.exe -sS -w "\nHTTP %{http_code}\n" http://127.0.0.1:8091/api/admin/diseases
```

上面的命令直接在命令提示符粘贴运行；若写入BAT文件，把 `%{http_code}` 改为 `%%{http_code}`。预期HTTP200、业务code为0、包含burn/scar。

测试前端会调用：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | /api/indicators/extract | 文本和Python检测JSON统一提取 |
| GET | /api/indicators/logs?requestId=编号 | 提取SSE日志 |
| POST | /api/reports/generate | 决策推理与八段报告 |
| GET | /api/reports/logs?requestId=编号 | 报告SSE日志 |

提取请求为requestId、diseaseCode（burn/scar）、clinicalText（非空文本）、featureResult（JSON对象）。返回indicators中文映射、indicatorCodes编码映射、timings、elapsedMs、errors。报告请求为diseaseCode、requestId、indicators，推荐提交前端编辑后的完整code/value映射。不要改字段名称。

生成报告时提交本次需要使用的全部指标；服务没有跨请求暂存图片指标的机制。SSE使用与对应POST相同的requestId；前端先订阅日志再发POST。没有health接口。管理API及数据结构可打开 http://127.0.0.1:8091/docs 查看。

**判断成功：**HTTP200仅说明请求完成，还要检查提取errors、报告warnings、实际指标值与报告内容。模型失败可能回退默认值；不能把默认值当作患者真实事实。当前代码和配置包含POSAS等计算路径，交接不等于临床准确性验证。

## 七 Linux 直接运行

BAT用于Windows。Linux安装相同运行环境后，在数据库首次导入前确认没有同名配置表，再执行：

```bash
mysql -h 127.0.0.1 -u root -p -e "CREATE DATABASE burn_treatment CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql --default-character-set=utf8mb4 -h 127.0.0.1 -u root -p burn_treatment < database/burn_ai_config.sql
```

数据库已存在时无需再CREATE。Linux手动导入不像Windows脚本自动检查已有表，请先核对目标数据库。`-p`会交互询问密码。

通过受限本地配置或终端环境变量配置上述BURN_AI_*变量，不提交凭据。在后端目录运行：

```bash
mvn --batch-mode --no-transfer-progress clean package
java -jar target/burn-ai-service-0.0.1-SNAPSHOT.jar
```

另开终端进入测试前端目录：

```bash
BURN_AI_BACKEND=http://127.0.0.1:8091 node server.js
```

前台运行时Ctrl+C关闭对应进程。页面地址为5179，远程访问还需要可达的网络和端口。

## 八 常见问题及测试

- mysql.exe找不到：填写MySQL客户端完整路径。
- 已有配置表：选择新库名，并更改Java连接URL。
- 数据库连接失败：确认MySQL服务、端口、用户、密码和库名；导入账号与Java账号可不同。
- Java版本报错：检查mvn -version实际使用的JAVA_HOME是否为JDK17。
- 模型失败或errors非空：检查provider、enabled、key、endpoint、模型名及模型服务是否启动。
- 端口占用：用状态/关闭脚本关闭原进程；脚本不会强杀其他占用者。
- 页面502：检查BURN_AI_BACKEND、后端运行及网络。

回归测试：在后端目录执行 `mvn test`。真实模型集成测试会产生请求和费用，需配置真实数据库与模型后显式运行；本次交接默认只运行离线回归和本地配置查询、启停测试。
